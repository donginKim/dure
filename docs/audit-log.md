# 감사 기록

두레는 누가 무엇을 했고 어떻게 됐는지를 한 줄씩 적는다. 납품과 점검에 쓰는 기록이다.
화면은 ⌘K → "감사 기록", 또는 설정 → 감사 기록 → "기록 열기".

## 적는 것과 적지 않는 것

적는 것은 **누가, 무엇을, 어느 대상에, 결과, 까닭**과 작은 덧붙임(개수, 길이, 모드 이름)이다.

**본문은 적지 않는다.** 프롬프트, 메시지의 글, SQL 과 조회 결과, 확인 명령의 글, 기억의 글, 비밀 값은 기록에 들어가지 않는다.
이름·종류·길이·개수만 남는다. (예: 에이전트에게 보낸 지시는 `agent.prompt` 와 글자 수만 남는다.)

## 누가 (actor)

| 값 | 뜻 | 어디서 적나 |
|---|---|---|
| `user` | 사용자가 화면에서 한 일 | 화면과 본체 사이의 통로(IPC). `src/main/auditIpc.ts` 의 표에 있는 채널만 |
| `agent` | 에이전트가 두레의 도구를 부른 것 | MCP 서버. 도구 이름과 성공·실패만. 두레 안의 것을 읽기만 하는 도구는 적지 않는다 (DB·슬랙·브라우저 도구는 읽기여도 적는다) |
| `system` | 두레가 스스로 한 일 | 자동 반영, 예약 실행, 자리 비움의 대신 답하기, 에이전트 실행, 리뷰·만들기의 모델 호출, 오래된 기록 삭제 |
| `peer` | 다른 사람(다른 PC 의 두레)이 한 일 | 아직 적지 않는다 (아래 "아직 없는 것") |

## 한 줄의 모양

| 칸 | 뜻 |
|---|---|
| `seq` | 줄 번호. 1 씩 오른다 |
| `at` / `time` | 때 (밀리초 / ISO 8601, UTC) |
| `actor`, `actorName` | 누가, 그 이름 (에이전트면 워크스페이스 이름) |
| `action` | 무엇을. 점으로 나눈 영문 이름이고 바꾸지 않는다 (예: `db.query.decide`, `plugin.approve`, `tool.message_send`) |
| `projectId`, `workspaceId`, `target` | 어느 프로젝트·워크스페이스·대상 |
| `outcome` | `ok` 됨 / `denied` 거절·보류 / `failed` 실패 |
| `reason` | 까닭 (오류의 글, 자동 반영이 멈춘 까닭 등) |
| `detail` | 덧붙임 (JSON 글) |
| `prev`, `hash` | 앞 줄의 지문, 이 줄의 지문 |

## 동작 이름 (action)

| 앞머리 | 담긴 것 |
|---|---|
| `agent.*`, `shell.open` | 에이전트 시작·실행·끄기·멈춤, 지시, 실행 승인 응답(`agent.permission`), 질문 응답 |
| `tool.<도구 이름>` | 에이전트의 도구 호출 |
| `agent_config.trust` | 저장소의 에이전트 설정 파일(.claude/settings.json, .mcp.json) 허용 |
| `away.*` | 자리 비움이 대신 답한 것 (`denied` 는 되돌리기 어려운 일이라 고르지 않은 것) |
| `model.call` | 리뷰·만들기의 모델 호출 (모델 이름과 토큰 수) |
| `plan.*`, `todo.*`, `schedule.*`, `memory.*`, `agreement.*`, `message.*` | 계획안 승인·거절, 할 일, 예약, 기억, 약속, 메시지 |
| `commit.*`, `merge.*`, `autoship.*`, `pr.*`, `checkpoint.*`, `verify.*`, `review.*`, `cleanup.*` | 커밋·push, 기준 브랜치 이동, 자동 반영의 단계와 멈춘 까닭 |
| `db.*`, `slack.*`, `browser.*` | 연결 등록, 조회·읽기 승인 응답 |
| `peer.*`, `share.*`, `assign.*`, `workspace.sharing` | 다른 사람과의 연결, 함께하는 프로젝트, 받은 일, 공개 범위 |
| `plugin.*`, `make.*`, `settings.update`, `project.*`, `repo.*`, `workspace.*`, `app.update` | 플러그인, 만들기, 설정(바뀐 항목의 이름), 프로젝트·저장소·워크스페이스 |
| `audit.*` | 기록 내보내기, 오래된 기록 삭제 |

## 변조를 알아채는 방법

줄마다 앞 줄의 지문(`prev`)과 이 줄의 내용으로 지문(`hash`)을 만든다.

```
hash = sha256(JSON.stringify([prev, at, actor, actorName, action, projectId, workspaceId, target, outcome, reason, detail]))
```

`detail` 은 저장된 JSON 글 그대로다. 첫 줄의 `prev` 는 빈 글이다 (오래된 줄을 지운 뒤에는 지운 마지막 줄의 지문).
어느 줄을 고치거나 빼면 그 줄부터 지문이 어긋난다. 화면의 "이어짐 확인" 이 어긋난 첫 줄의 번호를 알려 준다.

**한계**: 같은 PC 의 같은 계정이 DB 파일을 통째로 다시 쓰면(모든 지문을 새로 계산) 알아챌 수 없다.
이것을 막으려면 기록을 주기적으로 내보내 다른 곳에 보관하고, 내보낸 묶음의 마지막 지문(`head`)을 따로 적어 둔다.

## 내보내기

- **JSONL**: 첫 줄은 묶음의 설명(`type: "meta"`: 형식 `dure-audit/1`, 내보낸 때, PC 이름, OS 사용자, 앱 판, 줄 수, 이어짐 확인 결과, 마지막 지문)이고, 그 뒤로 한 줄에 기록 하나다. 받는 쪽이 위 식으로 이어짐을 다시 확인할 수 있다.
- **CSV**: 표 계산 프로그램에서 여는 용도다. 수식으로 읽힐 수 있는 값은 앞에 `'` 를 붙인다.
- 화면에서 거른 조건(기간, 누가, 결과, 프로젝트) 그대로 나간다. 내보낸 것도 `audit.export` 로 기록된다.

## 보관 기간

설정 → 감사 기록 → 보관 기간 (기본 365일, 0 이면 지우지 않는다). 지난 줄은 두레를 켤 때 지우고 `audit.prune` 을 남긴다.

## 아직 없는 것

- 다른 사람(피어)이 보낸 것의 기록 (연결 요청, 받은 메시지, 받은 일). 지금은 사용자가 그것에 답한 것만 남는다.
- 에이전트가 두레의 도구를 거치지 않고 한 일 (터미널 명령, 파일 수정). 에이전트 제품 자체의 기록에 있다.
- 기록을 밖의 수집 서버로 바로 보내는 것 (syslog, SIEM).
- 규칙(정책)에 따른 판정의 근거 번호. 정책 표를 만들면 `reason` 에 싣는다.
