# 비서: 모든 프로젝트를 보는 에이전트

2026-11-20. 브랜치 `feat/dure-steward`.

## 왜
조율 에이전트는 프로젝트마다 하나라 자기 프로젝트만 본다. 프로젝트를 가로지르는 것은 "확인할 것" 과 아침 브리핑뿐이고 둘 다 보여 주기만 한다. 사용자는 모든 프로젝트를 놓고 말을 걸 상대를 원한다: 전체 TODO 를 관리하고, 브리핑하고, 밀린 승인을 처리해 주는 "나만의 봇".

## 사용자가 정한 것
- 하는 일: 모든 프로젝트의 TODO 관리, 브리핑, 밀린 승인 처리.
- 승인은 "전부 스스로" 를 원했다 (위험을 듣고도). 그 범위는 설정으로 바꿀 수 있게 한다.

## 방식
- **가. 보이지 않는 프로젝트의 조율 자리 (고름)**: 두레가 관리하는 프로젝트(`projects.kind = 'steward'`)를 하나 두고, 그 조율 자리(role `coordinator` 인 워크스페이스)에 비서를 둔다. 채팅 화면, hook, MCP 토큰, 예산, 감사 기록 같은 조율 에이전트의 틀을 그대로 쓴다. `ProjectStore.list()` 는 사용자의 프로젝트만 돌려준다.
- 나. 프로젝트에 묶이지 않는 워크스페이스: 워크스페이스가 프로젝트를 참조한다는 전제가 코드 곳곳에 있어 고칠 곳이 많다.
- 다. 에이전트 없이 규칙으로만 처리: 브리핑과 판단을 할 수 없다.

## 동작
- 화면: 왼쪽 "확인할 것" 아래에 비서. 누르면 대화와 "비서가 처리한 것" 기록.
- 설정 (설정 > 비서): 이름, 승인 범위, 자동 처리, 모델.
- 비서의 도구 (비서에게만 실리고, 비서에게는 이것만 실린다. 셸과 파일 고치기 도구도 없다):
  `steward_overview`, `steward_todos`, `steward_todo_add`, `steward_todo_update`, `steward_todo_remove`, `steward_waiting`, `steward_decide`, `steward_tell`.
- 자동 처리를 켜면, 확인할 것이 새로 생겼을 때 두레가 잠깐 모았다가 비서에게 알린다. 비서가 정할 수 있는 것이 없으면 깨우지 않는다.

## 승인 범위 (두레가 지킨다: `StewardService.need()`)
| | 추천만 | 안전한 것만 (기본) | 전부 스스로 |
|---|---|---|---|
| 경고 없는 DB 조회, 슬랙 읽기, 이 PC 의 개발 서버 주소, 멈춘 에이전트 깨우기 | 추천 | 정함 | 정함 |
| 되돌릴 수 있는 선택지 질문 | 추천 | 추천(첫째) 답만 | 어느 답이든 |
| 명령 실행 허용, 계획안, 약속, 경고 있는 DB 조회, 바깥 주소, 다른 사람의 메시지·받은 일·기획서 정리·초대 | 추천 | 추천 | 정함 |
| 연결 요청의 확인, 나에게 직접 온 질문, 예산·사용 한도·자동 반영 실패 | 사용자 | 사용자 | 사용자 |

어느 범위에서도:
- 정할 때마다 까닭(reason)을 적어야 하고, 감사 기록과 `steward_log` 에 남는다. 범위 밖을 시도한 것도 남는다.
- 에이전트의 권한 요청·질문은 요청 번호(request)가 맞아야 한다: 비서가 본 요청과 정하는 요청이 같아야 한다.
- 내용이 길어 다 보이지 않는 요청은 정하지 않는다.
- 비서 자신의 요청은 확인할 것에 들지 않는다 (스스로 승인할 수 없다).

## 비서가 속을 수 있다는 것
비서는 에이전트의 출력과 다른 사람의 글을 읽고 판단한다. 그 글이 비서를 속여 허용하게 만들 수 있다. 그래서:
- 범위는 지침이 아니라 코드가 지킨다. 기본은 "안전한 것만" 이다.
- "전부 스스로" 는 권한 단계 "삭제만 묻기" 가 묻는 것도 비서가 대신 답한다는 뜻이다. 설정 화면에 그렇게 적었다.
- 비서가 다른 에이전트에게 전하는 글과 비서가 바꾼 TODO 에는 비서가 한 것임을 적는다. 사용자가 직접 한 것으로 읽히면, 비서를 속인 글이 사용자의 권위를 얻는다.
- 비서에게는 셸이 없다: 속아도 이 PC 에서 명령을 실행할 길이 없다.

## 남은 것 (이번에 하지 않음)
- 예산을 올리거나 모델을 바꾸는 일을 비서가 대신하기.
- 받은 일을 수락할 때 내 저장소 고르기 (지금은 새 저장소의 이름만 받는다).
- 비서가 답을 기다릴 때 옆 메뉴에 표시하기.
- 사람 없이 에이전트와 비서가 주고받는 횟수의 상한 (지금 막는 것은 비서의 하루 예산뿐이다).
- 슬랙·텔레그램 같은 바깥에서 비서를 부르기.

## 확인
- `tests/core/steward.test.ts` (자리, 현황, TODO, 범위별 결정, 도구가 누구에게 실리는지, 전하기, 자동 알림, 설정), `tests/core/stewardScope.test.ts` (종류마다의 범위, 요청 번호, 잘린 내용, 질문의 답).
- 실제 앱: 브리핑, TODO 추가, "안전한 것만" 에서 삭제 승인을 남기고 추천만 하는지, "전부 스스로" 에서 허용하고 기록을 남기는지, 조율 에이전트에게 전한 글에 비서가 쓴 글이라고 적히는지.
